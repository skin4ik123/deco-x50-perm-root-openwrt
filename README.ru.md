# Deco X50: постоянный root и OpenWrt в RAM

[English](README.md) · **[Скачать релиз v1.1.1](https://github.com/skin4ik123/deco-x50-perm-root-openwrt/releases/tag/v1.1.1)**

Приложение **Deco Control** на английском языке: установка root, переключение устройств, SSH-терминал, файловый менеджер, диагностика и мастер запуска OpenWrt через Windows/TFTP.

**Важно:** root сохраняется в штатной прошивке. Мастер приложения запускает OpenWrt временно, в RAM. **Из уже запущенной RAM-системы можно установить постоянную OpenWrt — этот путь подтверждён владельцем на Deco X50 V1.** Постоянная установка выполняется отдельно с подходящим образом; мастер не прошивает его автоматически. Проект экспериментальный.

## Подойдёт ли мой роутер?

Проверенный профиль — **обычный Deco X50 V1 EU, hardware 1.0, Qualcomm IPQ5018/aarch64, штатное ядро 4.4.60** и конкретные отпечатки OEM-кода. Сверь наклейку снизу. Приложение дополнительно проверяет совместимость; одинакового номера ядра недостаточно.

**Не подходит для X50 V3/MediaTek, M4/M4R и непроверенных ревизий/регионов.** Нельзя обходить отказ приложения, выбрав другую модель. На телефоне нужен Android 8+ и ARM64.

Root настраивается без автоматической перезагрузки. Запуск OpenWrt отдельно перезагрузит выбранный Deco и отключит его от штатной сети. Запускай это на одном устройстве, когда им можно временно не пользоваться. При записи boot environment питание должно быть стабильным: на этом устройстве его копия одна.

## Шаг 1. Установить приложение и добавить Deco

1. Скопируй APK на телефон и открой. Если Android спросит разрешение установки, разреши его для того браузера/файлового приложения, которым открываешь APK.
2. Подключи телефон к обычному Wi-Fi твоей Deco-сети.
3. Найди текущий IP нужного Deco в официальном приложении TP-Link, в информации об устройстве. У главного узла и сателлитов могут быть разные адреса.
4. В Deco Control открой **Devices**, добавь устройство, введи имя и его IP. Готовых адресов чужой сети в приложении нет.
5. Открой добавленное устройство. Убедись, что выбрано именно оно.

Если root уже есть, нажми **Already have root? Sign in**, введи `root` и действующий SSH-пароль. Устанавливать root второй раз не требуется.

## Шаг 2. Получить root

1. В **Overview** выбранного Deco нажми **Set up root**.
2. В поле **Mesh controller IP address** введи IP **главного Deco**. При работе с сателлитом здесь всё равно нужен главный Deco, а выбранным устройством остаётся сателлит. Это не адрес внешнего MikroTik.
3. **Owner email or SSH username** — обычно email владельца сети из аккаунта TP-Link.
4. **Owner password** — пароль этого аккаунта владельца. Это **не пароль Wi-Fi** и не новый root-пароль. Проверка идёт через локальный сервис штатной прошивки, не через облачный вход. Продвинутый вариант — уже известное 40-символьное hex-имя OEM SSH.
5. Нажми **Check owner access**. Дождись **Owner access verified**. Этот этап только проверяет доступ.
6. Введи отдельный **New password** длиной не менее 12 символов и повтори его в **Repeat password**. Сохрани пароль у себя.
7. Подтверди **Deco X50 · V1 · EU**, если это действительно твоя модель. Нажми **Install root** один раз.
8. Приложение проверит отпечатки и сохранит конфигурационный бэкап до изменения. Само по себе получение root роутер не перезагружает.
9. Подключайся к выбранному IP как `root`, порт `22`, с новым паролем. Терминал и файлы находятся в соответствующих вкладках.

Root-сервис и его отдельные данные сохраняются в постоянных данных штатной системы и запускаются через startup hook. При удобном случае после обычной перезагрузки используй **Verify startup**. Сохранение после обновления штатной прошивки или сброса к заводским не гарантируется. Изменение IP тоже может сделать привязанный сервис недоступным.

Сохрани бэкап отдельно в личном хранилище. Не отправляй конфигурацию, NAND-копии, журналы операций и пароли в GitHub Issues. NAND DATA backup не содержит OOB и не является проверенной инструкцией восстановления.

## Шаг 3. Подготовить ноутбук Windows

Нужны ноутбук, Ethernet-кабель и TFTP-сервер. На телефоне Termux/Python не нужны.

1. Соедини ноутбук кабелем **напрямую с тем X50**, который будешь запускать в OpenWrt. Телефон пока остаётся на штатном Wi-Fi.
2. Нажми на ноутбуке **Win+R**, введи `ncpa.cpl`, нажми Enter.
3. Найди **Ethernet**, нажми правой кнопкой → **Свойства** → **IP версии 4 (TCP/IPv4)** → **Свойства**.
4. Выбери ручной адрес:

| Поле | Значение |
|---|---|
| IP-адрес | `192.168.1.2` |
| Маска | `255.255.255.0` |
| Основной шлюз | оставить пустым |
| DNS | оставить пустым |

5. Скачай Tftpd64 из [официальных Releases](https://github.com/PJO2/tftpd64/releases). Установи/запусти и создай папку `C:\TFTP`.
6. В Tftpd64 задай **Current Directory** = `C:\TFTP`. Включи TFTP-сервер, **выключи DHCP-сервер**.
7. В настройках TFTP ограничь/bind сервер адресом Ethernet `192.168.1.2`. В новых Tftpd64 выбор адреса только в выпадающем списке не ограничивает все интерфейсы. Проверь именно настройку привязки.
8. Разреши Tftpd64 через брандмауэр Windows для этого подключения. Выключать брандмауэр целиком не нужно.

После эксперимента верни Ethernet к автоматическому получению IP и DNS.

## Шаг 4. Положить правильную прошивку в TFTP

В Deco Control открой **Tools → OpenWrt RAM boot**. Можно также открыть карточку OpenWrt в **Overview** устройства.

Вариант A: нажми **Download verified RAM image · 12.5 MiB**, дождись проверки, затем **Share image to laptop** или сохрани файл и перенеси на ноутбук.

Вариант B: скачай на ноутбуке [этот точный файл](https://github.com/Oein/Deco-X50-Firmware-Unpack/releases/download/deco-x50-v1-r37324.2/openwrt-qualcommax-ipq50xx-tplink_deco-x50-v1-initramfs-uImage.itb).

Положи его в `C:\TFTP`. Имя должно остаться **точно таким**:

```text
openwrt-qualcommax-ipq50xx-tplink_deco-x50-v1-initramfs-uImage.itb
```

Размер — **13 056 916 байт**. SHA-256:

```text
ce2c49c0fb6dadea9e6430cba9a39ca03f833bb6b20df7d63a9d0ddefeec4ee2
```

Для проверки в PowerShell:

```powershell
Get-FileHash "C:\TFTP\openwrt-qualcommax-ipq50xx-tplink_deco-x50-v1-initramfs-uImage.itb" -Algorithm SHA256
```

Включи показ расширений файлов в Проводнике: не должно получиться `.itb.itb` или `.itb.bin`. Не подсовывай NSS-образ, sysupgrade, factory/recovery или изменённый файл, переименовав его. Мастер 1.1.1 проверяет размер/CRC именно исходного образа.

## Шаг 5. Запустить OpenWrt в RAM

1. В мастере сверь выбранный Deco.
2. **Laptop Ethernet IPv4 address** = `192.168.1.2`, как на ноутбуке.
3. Отметь **The TFTP server is running with this exact image**.
4. Нажми **Check compatibility and back up**. Пока идёт эта подготовка, штатная прошивка продолжает работать. На телефон сохраняется boot environment backup.
5. После **Ready for a RAM boot** нажми **Boot OpenWrt in RAM**. Ещё раз сверь устройство и подтверди **Boot OpenWrt**.
6. Deco перезагрузится. На ноутбуке следи за передачей в Tftpd64. Если передачи нет, проверь кабель, IP, firewall, имя файла и папку TFTP; не запускай Boot заново.
7. На телефоне подключись к появившемуся **X50-OpenWrt**.
8. В приложении нажми **Verify OpenWrt over SSH**. Оно проверяет не просто наличие SSH, а устройство, новый boot ID и метку именно этой попытки загрузки.
9. После успешной проверки доступны **Open OpenWrt terminal** и **Open LuCI**. Веб-интерфейс: **http://192.168.1.1/**.

Изначально этот тестовый образ раздаёт открытый Wi-Fi и имеет пустой root-пароль. Держи эксперимент изолированным. Проверку в приложении выполни до смены пароля; её начальный RAM-вход в версии 1.1.1 рассчитан на пустой пароль. После установки собственного пароля пользуйся обычным SSH с ноутбука/LuCI для новых подключений.

Это не постоянная прошивка. Сам initramfs не записывается в NAND, но до перезагрузки мастер записывает одноразовую команду в boot environment. Загрузчик восстанавливает штатную boot policy **до** TFTP.

## Шаг 6. Если Ethernet не работает — исправить switch

Это отдельная известная проблема **classic RTL8367S 6367/00a0, CPU6/extif1** в исходном образе. Она проявляется отсутствием switch0 и сообщениями `HSGMII is only supported on RTL8367S-VB extif0` / `chip setup failed, err=-22`. Просто ручной IP её не лечит. Для другого образа/варианта железа этот модуль не применять.

Если Ethernet уже работает, этот шаг пропусти.

1. Распакуй `Deco-Control-X50-Ethernet-RAM-v1.zip` на ноутбуке.
2. Подключи Wi-Fi ноутбука к **X50-OpenWrt**. Временно вытащи Ethernet-кабель: иначе Windows может отправлять пакеты через неработающий провод вместо Wi-Fi.
3. Запусти **Upload-Windows.cmd** из распакованной папки. Он проверяет KO и копирует helper/модуль в `/tmp`, но не применяет их.
4. Если Windows спрашивает доверие SSH-ключу, проверь, что подключаешься к своему X50. В исходном RAM-образе пароль пустой — при запросе достаточно Enter. Если уже задал пароль, введи свой.
5. Открой PowerShell и введи:

```powershell
ssh root@192.168.1.1
```

Если команды `ssh`/`scp` нет, установи встроенный компонент Windows **Клиент OpenSSH** через «Дополнительные компоненты». Это не SSH-сервер на ноутбуке.

6. После появления приглашения `root@OpenWrt:~#` вставь **один раз**:

```sh
sh /tmp/InternetDeco_X50_Ethernet_RAM_v1.sh --apply
```

Нужны строки `FAMILYC_DRIVER_REGISTERED=1`, `DRIVER_BOUND=1`, `MODULE_STATE=live` и появившийся `switch0`. `VLAN_APPLY_NOT_RUN=1` пока нормально — требуется второй шаг.

7. Затем **один раз** выполни:

```sh
swconfig dev switch0 load network
swconfig dev switch0 show
```

Дополнительный `set apply`, `uci commit` и перезапуск network/Wi-Fi не нужны. CPU/VLAN port должен остаться **6** — аппаратный MAC alias 8 не означает CPU port8.

8. Подключи кабель в LAN-разъём (исходная схема — верхний/средний). В Windows верни **автоматические IPv4 и DNS**, временно выключи Wi-Fi ноутбука и открой **http://192.168.1.1/**.

Проводной доступ после этих двух шагов подтверждён на реальном устройстве. Все разъёмы, длительная нагрузка и максимальная скорость отдельно не подтверждены. Это не исправление NSS и не инструкция для другого NSS-образа с таким же номером ядра.

Если helper оборвался или результат неизвестен, выполняй только просмотр:

```sh
sh /tmp/InternetDeco_X50_Ethernet_RAM_v1.sh --status
```

Не повторяй `--apply`, не удаляй marker и не пытайся насильно откатить драйвер. Исправление действует только в текущем RAM-сеансе. Оба шага не записывают NAND/MTD, прошивку или boot environment.

## Шаг 7. Вернуться на штатную прошивку

После подтверждённой загрузки в RAM выключи и снова включи питание. Телефон верни на прежний Wi-Fi. В приложении нажми **Check stock state at …** для исходного адреса Deco. Состояние должно быть согласовано, прежде чем готовить следующую попытку.

Если приложение сообщало неизвестный результат записи/перезагрузки, сначала используй сохранённое состояние и проверку/guarded **Restore stock boot policy**. Не удаляй данные приложения и журналы, пытаясь разблокировать Boot.

**Кнопка Reset, sysupgrade, mtd write и запись UBI в этой инструкции не используются.**

## Частые вопросы

**Долго подключается SSH.** По умолчанию на handshake даётся 90 секунд и до трёх транспортных попыток. В Settings можно выбрать 30–120 секунд и 1–3 попытки. Смотри этап и счётчик. Неверный пароль/изменившийся ключ не исправляются повторными попытками. Команды записи автоматически не повторяются.

**TFTP не передаёт файл.** Проверь, что сервер — ноутбук `192.168.1.2`, а не роутер; файл лежит в его Current Directory, имя и расширение точные, сервер привязан к Ethernet и разрешён в firewall. Не включай DHCP-сервер Tftpd64. Отсутствующий файл может оставлять загрузчик в ожидании.

**На Windows «Неопознанная сеть» и 169.254…** Сам по себе статус Windows не доказывает загрузку OpenWrt. До старта TFTP нужен заданный вручную `192.168.1.2`. После загрузки проверь Wi-Fi и Verify в приложении. Если есть конкретная ошибка classic switch, нужен шаг6; бесконечная смена IP не поможет.

**Wi-Fi есть, по проводу никак.** Для указанного classic-чипа сначала драйвер, затем `swconfig dev switch0 load network`. Применение только первой команды недостаточно.

**Поменял root-пароль OpenWrt, приложение больше не проверяет RAM.** Начальный RAM verifier 1.1.1 ожидает пустой пароль исходного образа. Используй уже проверенную сессию или обычный SSH/LuCI с новым паролем; штатный root-пароль сохранён отдельно.

**Переустановить root или стереть журнал после ошибки?** Нет. Сохрани состояние, прочитай точную ошибку и используй проверки/восстановление. Потеря связи не равна отсутствию root.

**Можно затем установить OpenWrt постоянно?** Да. Установка постоянной OpenWrt из запущенной RAM-системы подтверждена владельцем на X50 V1. Для неё нужен подходящий образ и отдельный шаг установки; данный мастер автоматически его не выполняет. Отдельная Mesh Manager/NSS-прошивка в этот релиз не входит.

## Что проверено и что сообщать об ошибке

Root-провижининг более ранней версии, TFTP-загрузка исходного образа и отдельное исправление Ethernet подтверждены владельцем на железе. Для APK1.1.1 записаны 44 Rust и 83 JVM теста, проверки JNI/хранилища, подписи и 16KiB alignment. Это не заменяет полного теста именно мастера1.1.1 на телефоне. Постоянная установка OpenWrt из RAM дополнительно подтверждена владельцем на X50 V1. Сохранение stock-root после OTA/сброса не проверено.
